# Secure Liberty 200 — Real-World Simulation Context

## Overview
The APT Simulator incorporates telemetry, behaviors, and event codes derived from real-world prepaid smart meters used in Indian DISCOM grids, specifically modeled after the **Secure Liberty 200** single-phase smart meter.

By anchoring the simulation in physical realities of actual hardware rather than abstract "IoT devices", the attack kill-chains become more credible and represent genuine operational technology (OT) vulnerabilities.

## DLMS/COSEM Integration
Secure Liberty 200 operates using the DLMS/COSEM (Device Language Message Specification / Companion Specification for Energy Metering) protocol. 
In our simulation, the telemetry generated by the `MeterAgent` maps to standard OBIS (Object Identification System) codes:

* **Active Power (W):** `1.0.1.7.0.255`
* **Maximum Demand (kW):** `1.0.1.6.0.255`
* **Total Energy Consumption (kWh):** `1.0.1.8.0.255`
* **Battery Voltage (V):** `0.0.96.6.0.255`

## Physical Tampering & Recharge Tokens
A defining feature of the Liberty 200 is its numeric keypad and optical port used for entering 20-digit STS (Standard Transfer Specification) encrypted recharge tokens.

### The Attack Vector (T0834 - Hardware)
Our simulation includes a dedicated "Physical Tampering" stage:
1. **Optical Port Access:** The attacker physically accesses the meter or optical probe.
2. **Token Injection:** They attempt to inject a malformed, replayed, or brute-forced 20-digit recharge token (e.g., `2938 1234 9876 5432 1098`).
3. **Meter Response:** The Liberty 200 cryptographic engine rejects the token due to an invalid signature or duplicate sequence number.
4. **Event Generation:** The meter logs a `TOKEN_REJECTED` or `REFUND_GENERATED` event, which is transmitted via the WAN (cellular) or HAN (RF Mesh) back to the Head-End System (HES).

### Detection
The simulation's detection engine monitors the HES event bus. A sudden burst of `TOKEN_REJECTED` events from a specific meter triggers a **Physical Tamper Signal**, raising the composite risk score and alerting the SOC to potential on-site hardware manipulation before network-based lateral movement even begins.

## Key Telemetry Fields Added
To support this realism, the following fields were added to the simulator's data model:
- `max_demand_kw`: Peak load recorded.
- `battery_voltage`: Internal RTC battery health.
- `power_fail_count`: Lifetime grid outage count.
- `diag_status`: Self-diagnostic flags (e.g., Cover Open, Magnetic Tamper).
- `wan_status` / `han_status`: Network link health (Good/Poor).

## Conclusion
This grounding transforms the simulator from a generic IT network attack into a specialized, grid-aware OT security demonstration, highlighting the convergence of physical hardware tampering and cloud-based C2 orchestration.
